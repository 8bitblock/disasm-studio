# DisasmStudio

A fast, GPU-accelerated reverse-engineering workbench built with **Dear ImGui** and **DirectX 11** in C++20. It combines bounded multi-format static analysis, a real Win32 debugger, guided network/crackme investigation, memory and patch tooling, and persistent multi-document analysis behind engine-neutral Zydis/Capstone/JVM/GML decoding.

**GameMaker / Nubby debugging:** open `data.win`, attach the game in Communications,
then start **GameMaker / GML** debugging. Named instruction breakpoints, call-aware
stepping, scoped watches and checked numeric edits use an embedded x64 helper for
the verified Nubby runner. See the [usage guide](docs/GAMEMAKER_DEBUGGING.md) and
[implementation evidence](docs/GAMEMAKER_IMPLEMENTATION.md).

## Build

### Prerequisites
- **Visual Studio 2022** with the "Desktop development with C++" workload (MSVC v143, Windows 10/11 SDK).
- **vcpkg** (https://github.com/microsoft/vcpkg). One-time setup:
  ```
  git clone https://github.com/microsoft/vcpkg
  .\vcpkg\bootstrap-vcpkg.bat
  .\vcpkg\vcpkg integrate install
  ```

The project uses **vcpkg manifest mode** (`vcpkg.json`), so the first build automatically downloads and builds ImGui (with the DX11 + Win32 + docking backends), Zydis, Capstone, and Keystone (the assembler behind the Patch feature). The repository overlay for `x64-windows-static` binds dependency compilation to the same VS 2022 installation and exact `v143` minor that MSBuild selected for the app. The overlay triplet and a generated toolchain-identity file are manifest-stamp inputs, so changing Visual Studio instances or toolset minors triggers dependency reevaluation instead of reusing ABI-incompatible C++ libraries. No edition, install path, or toolset minor is hardcoded.

### Compile
Open `DisasmStudio.sln` in Visual Studio 2022, pick **x64 / Debug** (or Release), and build (F7). The binary lands in `build\x64\<Config>\DisasmStudio.exe`. For command-line or CI builds, `build.ps1` locates only a complete VS 2022 C++ instance and passes its exact `v143` version to both MSBuild and vcpkg; `-VisualStudioPath` selects a particular side-by-side instance without hardcoding it in the repository.

Full verification uses a current Release build followed by every declared test:

```powershell
.\build.ps1 -Configuration Release
if ($LASTEXITCODE) { throw 'Release build failed' }
.\tests\run_core_tests.ps1 -Suite All
if ($LASTEXITCODE) { throw 'Verification failed' }
```

The build wrapper defaults to one MSBuild project and two compiler processes per project to bound memory use; `-MaxParallelProjects` and `-MaxCompileProcesses` allow explicit overrides. The test runner selects the same exact v143 toolset as the build. `All` includes the Core tests, all three production app-object suites (`static_listing_actions_test`, `release_workbench_test`, and `feature_tabs_ui_test`), and the x64, WOW64 and `authorization_watch_live_test` native debugger suites. `All` and `Live` require launch/debugger prerequisites; they fail if those prerequisites are unavailable. CI runs each category explicitly after its pinned-dependency Release build and retains verification logs.

For a faster local loop, `tests\run_core_tests.bat` defaults to `Core`; pass a test name to run one declaration, or `-Suite Integration` / `-Suite Live` to run a category. `-ListOnly` displays the exact selection without compiling or launching anything. Each run writes build/run logs and a machine-readable `summary.json` under `build/test-results`; failures return a nonzero exit code and preserve artifacts.

If the ImGui backend headers (`imgui_impl_dx11.h`, `imgui_impl_win32.h`) aren't found, confirm the `dx11-binding` and `win32-binding` features installed: `vcpkg install` from the project root reads `vcpkg.json`.

### Distribution (self-contained exe)
The project builds against the **`x64-windows-static`** vcpkg triplet with the **static CRT** (`/MT`, `/MTd`),
so ImGui/Zydis/Capstone/Keystone and the C/C++ runtime are linked *into* the exe. The result is a
**single self-contained `DisasmStudio.exe`** — no `Zydis.dll`/`capstone.dll`/`keystone.dll` beside it and
**no Visual C++ Redistributable** required on the target. The only non-OS dependency is
`d3dcompiler_47.dll` (ImGui's DX11 backend compiles its shaders at runtime), which ships with Windows 10/11.

The app icon (window/taskbar + Explorer) is embedded via `src/app.rc` (`src/app.ico`). To regenerate the
multi-resolution icon, run `powershell -ExecutionPolicy Bypass -File gen_app_icon.ps1`.

## Using it

- **Binary View > Overview** gathers mapped entry points, code exports, named roots, and inferred function candidates with their evidence. Open a lead in Assembly or Pseudocode, follow its references, or jump to the file Strings, Functions, Bookmarks, and Imports panels. Coverage distinguishes unavailable and partial analysis from completed results; address zero remains valid. The main view selector becomes a dropdown when the window is narrow.

- Launch as **`DisasmStudio.exe <path>`** to open a target immediately; quoted paths, spaces, relative paths, and Unicode filenames are accepted.
- Press **F1** anywhere for the grouped debugger/navigation/assembly/live/hex/graph/decompiler reference. Help > About shows the executable version and runtime stack.
- The Binary View's filterable **Exports / Symbols** side panel shows PE aliases/ordinals/forwarders and normalized ELF `.dynsym`/`.symtab` symbols with kind, binding, visibility, size, and provenance; mapped targets navigate to code or Hex. Undefined ELF symbols appear in Imports.
- The **Resources** lower tab browses the PE resource directory as a Type→Name→Language tree, decodes manifests / version info / string tables (hex for the rest), navigates to a resource's bytes in Hex, and saves resources verbatim or as reconstructed `.bmp`/`.ico`.
- **File > Open Binary** loads an `.exe/.dll/.sys/.bin` (PE/ELF/Mach-O auto-detected); **Open as Raw…** maps a flat blob as one complete executable `.raw` section with editable base, **entry point**, and architecture (including **x86-16 real mode, A32, Thumb/Thumb-2, and A64**). Before showing the dialog, a bounded firmware probe recognizes corroborated legacy BIOS, PI/UEFI firmware-volume, PCI option-ROM, and Intel Flash Descriptor evidence, and separately scores coherent A32/Thumb/A64 call/frame/return motifs. It can prefill a safe mapping/mode, recover a boot target through common x86 reset/initialization jumps, and optionally seed named code landmarks. Every detected value remains editable, VA 0 is valid, and the chosen entry must be backed by the mapped file. Raw files use the normal background functions/listing/xrefs/call-graph pipeline. **Save Binary As…** writes a patched copy. The Projects tab lists recent targets and saved-analysis summaries.
- **File > Debug DLL…** validates the loaded PE DLL, offers only callable non-forwarded code exports, and launches it through a bitness-matched trusted Windows `rundll32.exe` or a bitness-validated custom host. Arguments are Windows-quoted from explicit DLL/export/user fields; optional DllMain/export stops are planted when the target `LOAD_DLL` event supplies its actual ASLR base, then Binary View analyzes the mapped DLL instead of the host.
- The Binary View's **Sections** side panel controls which loader sections participate in the linear listing and whether each is folded. Executable sections default visible/unfolded; optional data sections and the modeled **PE Header** default hidden/folded. Unfolded data renders 16-byte `db` rows with honest truncation markers (1 MiB per data region, 4 MiB total directive bytes); these view choices persist by stable `(RVA, name)` keys.
- **File > Save ASM… / Save C…** exports either the whole analyzed program or the function under the cursor. ASM supports every active decoder; x86/x64 C export offers the decompiler's readable pseudo-C or a self-contained, compilable C11 translation unit. Generation and file writing run on a dedicated background worker with progress and Cancel, independently of load-time analysis.
- **Engine** menu switches between Zydis and Capstone and the target architecture at runtime — the Binary View re-disassembles immediately.
- The top **debug toolbar** drives Continue / Step Into / Step Over / Step Out (also F5 / F11 / F10 / Shift+F11) and **Trace**. Trace incrementally plants up to 65,536 invisible one-shot basic-block breakpoints, shows planning/planting progress with cancellation, preserves collected hits when stopped, and offers **Clear Trace**.
- The UI is a fixed, browser-style single window: a top tab strip switches between Projects / Communications / Sig Scanner / Binary View / Memory Tools / Binary Diff / Binary Tech / Cortex / Prism, with the debug toolbar pinned above and a status bar below (no docking / tear-off windows, by design).
- Most result lists (Sig Scanner matches, Binary Tech capabilities, Imports, functions, strings) are click-to-navigate: selecting an address jumps the Binary View to it.

## What's real vs. stubbed
**Working now:**
- PE parsing, VA↔file translation, live disassembly (both engines).
- Byte-pattern signature scanning with `??` wildcards, ASCII string extraction, byte search, and binary diffing by bytes, sections, or semantic function structure.
- **Live process enumeration** (Toolhelp32) and **a real Win32 debugger** (`Debugger`): attach/detach via the debug API, software breakpoints (0xCC with the restore→single-step→re-arm dance), **Step Into** (EFLAGS trap flag), **Step Over** (temp breakpoint after a `call` or a `rep`-prefixed string op, single-step otherwise), **Step Out** (single-steps the current frame while *stepping over* every call, then stops on that frame's own `ret` — it never traces into callees, so it stays fast), register capture via `Get/SetThreadContext`, and `ReadProcessMemory`. Continue / Step Into / Step Over / Step Out all resume correctly even when issued while the thread is parked *exactly* on a software breakpoint: the engine restores + steps the original instruction, re-arms the 0xCC, and only then carries out the requested command. The per-instruction stepping decisions live in a pure, unit-tested header (`Core/StepLogic.h`; see `tests/step_logic_test.cpp`). The toolbar drives it; the debug loop runs on its own thread and the UI reads a lock-guarded snapshot.
- **Execution trace / coverage** (`Core/TraceCoverage`): from a paused session, the UI plans analyzed basic-block starts in bounded chunks and the debug thread plants invisible one-shot `int3` breakpoints. A hit restores the pristine byte, records coverage, retires the site, and continues; user, temporary step/run, JVM, and other explicit breakpoints keep priority at colliding addresses. Executed instructions/blocks glow green in the static assembly listing, Live Assembly, and CFG. Stop/cancel removes outstanding sites without erasing hits; **Clear Trace** resets them.
- **Debug-a-DLL** (`Core/DllDebugPlan`): PE DLL characteristics, bitness, entry point, and callable exports are validated before launch. The dialog supports a trusted bitness-matched `System32`/`SysWOW64` `rundll32.exe` or custom executable, correct Windows argument quoting, and DllMain/export breakpoints that remain RVAs until the matching `LOAD_DLL` event retargets them to the loaded ASLR base. The resulting live module feeds the normal analysis/listing pipeline.
- **Adaptive unpacker** (`Core/UnpackEngine` + `Core/PeUnpack`): **Debug -> Adaptive Unpack** combines stack-return, changed-page execution, newly executable pages, timed entropy settling, run-free, control-transfer, and manual OEP evidence instead of trusting one brittle heuristic. It can contain a fresh launch in a one-process kill-on-close Windows Job, scores every OEP candidate with visible evidence, and emits bounded VM-dispatch/handler/back-edge telemetry. The dump path reconstructs aligned PE32/PE32+ disk sections, restores or rebuilds imports from exact live exports, normalizes relocations transactionally, repairs OEP/load-config cookie/CFG metadata, strips stale signature/bound/checksum state, retains a raw artifact on failure, and can load the saved result immediately for analysis.
- **Static packed-PE recovery** (`Core/StaticUnpack`): **Debug -> Static Packed-PE Recovery** validates VMProtect-style `PACKER_INFO` block tables, decodes LZMA1 with strict input/output/dictionary/candidate/allocation caps, independently tests bounded LZMA-alone fallbacks, and reconstructs through `PeUnpack` on an owned/path-backed cancellable worker. The worker verifies the source's exact size/hash before decoding, and patched images must be saved/reopened first. The modal exposes every block's source/destination/status/evidence and can save reconstructed disk, decompressed mapped, or raw failure artifacts with a report. OEP trust is explicit: validated results are labelled runnable (using a nested PE's own preferred base), while an unchanged packer entry produces a clearly named analysis-only PE that can still be loaded for inspection.
- **Passive process dump** (`Core/PassiveDump`): Communications process rows and **Debug -> Passive Process Dump** capture existing processes without debug attach, injection, target writes, or patches. Immediate/manual/page-change+entropy settling, optional coherent final suspension, suspended remote module/EAT snapshot plus local exact-export IAT recovery, strict page provenance, identity-checked discardable-page backfill, aggregate peak-memory admission, PE reconstruction, raw fallback, and reports are integrated. Runnable output requires a manual OEP validated on an exactly captured executable page and zero disk-backfilled pages; the UI distinguishes a validated OEP from an artifact downgraded by backfill. Launch/watch supports safely requoted arguments and an explicit working directory, uses no debug flags, and enforces mandatory pre-resume one-process Job containment.
- **Hide Debugger / anti-anti-debug** (`Core/AntiDebug` + `Debugger`): an all-off-by-default policy reversibly normalizes PEB and OS-heap-list-proven legacy-heap fields and mediates selected bounded trusted-system-ntdll exports, thread hide, invalid handles, exact-self thread/process contexts, debug registers, and clocks through executable image-owned traps. CET shadow-stack/IP validation disables synthetic-return hooks. RDTSC/RDTSCP discovery recursively follows decode-valid control flow only from the PE entry, fully validated x64 unwind roots, and trusted ntdll roots, capped per image/session. Live-seeded QPC/system/TSC values share real resumed-run intervals while excluding debugger-paused time; per-thread/same-address re-arm leases handle multicore events, warnings are bounded/deduplicated, and image-owned traps retire safely on unload. Live counters and an explicit capability report distinguish this user-mode coverage from direct-syscall, shared-data, generated-code, and kernel guarantees, which are out of scope.
- **Hardware breakpoints** (DR0–DR3): up to four debug-register breakpoints with full DR7 condition/length encoding, programmed onto every thread (including newly created ones) and DR6-based hit detection. Right-click an address in the assembly view to toggle one; managed in the Breakpoints panel.
- **Conditional breakpoints**: any software breakpoint can carry a condition expression (e.g. `rax == 0x10`, `rcx > 100`, `[rsp+8] != 0`) evaluated on the debug thread at hit time — the debuggee only stops when it's true, otherwise it silently re-arms and continues. Evaluator lives in `Cond.{h,cpp}` (registers, memory derefs with displacement, `== != < > <= >=`).
- **Run to cursor**: right-click any instruction → *Run to cursor* sets a one-shot temp breakpoint and continues.
- **Thread list + context switching** (Binary View → Threads lower tab): every debuggee thread with its RIP; select one to point the register/stack views at it, or *follow* to also move the disassembly cursor.
- **Registers + stack panel** (Binary View → Registers lower tab): full GPR/RIP/RSP/RFLAGS dump plus a live stack read through `Debugger::readMemory`, for the active thread. While paused, double-click a register and enter hex to replace its raw value, plain/quoted text to allocate a NUL-terminated UTF-8/byte string and point a data GPR at it, or `L"..."` for UTF-16LE. The compact Live Assembly register box exposes the same editor from its right-click menu. Text buffers are non-executable, bound to the exact debugger session/thread, and checked for WOW64 pointer width. A successful buffer remains target-owned across a live detach so a retained pointer does not become dangling (process exit reclaims it); resumed target code can overwrite the register normally.
- **Live Assembly view** (Binary View → *Live Assembly*): disassembles the *debuggee's* memory at RIP in real time. Inline execution controls (Continue/Pause, Step Into/Over/Out) and a state pill mean you can drive the debugger without leaving the listing. A **register/flags strip** shows all GPRs + decoded EFLAGS (ZF/CF/SF/OF/PF/AF/DF) and **amber-highlights any register that changed since the previous stop**. **Jump arrows** are drawn in a left flow gutter (lane-packed, colored for forward/backward/active, with off-window stubs). The line at RIP gets **inline register-value hints** parsed from its operands (e.g. `; rcx=0x.. rdx=0x..`). Following RIP **back-aligns the window** so the current instruction shows with leading context and **auto-scrolls** to stay centered. Branch targets are clickable (and double-click-to-follow) with **back/forward cursor history**, a goto box, a right-click menu (run-to-cursor, SW/HW breakpoints, copy address/bytes/instruction), and per-view toggles for the strip, arrows, and hints.
- **Memory Tools workbench**: opens a process through a passive, identity-bound memory session (no debugger attach) or reuses the exact active debugger session. Cancellable first/next scans cover signed and unsigned 8/16/32/64-bit integers, floats/doubles, AOB patterns with `??`, and UTF-8/UTF-16LE text; predicates include exact/not-equal, greater/less, between, changed/unchanged, increased/decreased, delta, and unknown-initial. Region/range/alignment filters feed chunk snapshots with compact candidate bitmaps, so the admitted scope keeps an exact full result count and pages rows instead of imposing a hit cap. Admission preserves physical-memory headroom for the atomic next-scan copy and reports any reduced coverage instead of risking system-wide paging. The tab also provides a selectable 256-byte hex/ASCII editor, searchable region browser, bounded pointer-chain search with module-relative roots, and a separately saved JSON address table. Loaded rows are disabled and unfrozen; constant/minimum/maximum freezing runs on an identity-checked worker and uses verified writes, while protected or executable writes require explicit authority. The toolbar and Ctrl+K can send the current Live RIP directly to the hex view.
- **Prism 2 explanatory profiler**: Automatic mode prefers a bounded real-time ETW kernel collector for sampled profiles plus target-scoped image/thread/context-switch-derived wait/I/O evidence, with visible stack/frame coverage and lost-event quality. Policy/privilege failures are surfaced and use a labelled suspend-and-walk fallback with native x64 and WOW64 contexts. A separate worker builds immutable function/state/path/timeline/flame reports, and clicks map to an exact static image when proven or to live assembly for the matching attached PID.
- **Automatic function discovery** (`FunctionAnalyzer`): structured/raw entry + firmware landmarks + PE and ELF function/IFUNC symbols, recursive-descent call following, exact ELF size hints, architecture-gated x86/A32/Thumb/A64 prologues, and bounded ARM literal-pool exclusion. Thumb low-bit targets are canonicalized and decoder-mode-switching `BLX` edges are not followed through the wrong ISA. **1.0 scope:** ARM32 documents use one fixed A32 or Thumb decoder mode; per-address mixed-mode interworking is explicitly not claimed as authoritative.
- **Recursive code/data classification** (`CodeDataClassifier`): the background analyzer recursively follows proven control flow, then combines instruction references, strings, ARM-family literal pools, absolute/RVA/relative jump tables, aligned vtable/code-pointer runs, relocation-backed callbacks, CET landing pads, and ISA-aware padding into a complete confidence/evidence-bearing executable-byte map. Strong indirect targets get one bounded function-discovery feedback pass, so callback- or vtable-only functions become navigable. Classified data islands are shown inline as clipped, symbol-aware `db`/`dw`/`dd`/`dq` rows and split lazy decode checkpoints; uncertain bytes remain explicitly unknown.
- **Bounded derived-analysis cache** (`Core/AnalysisCache`): deterministic string, function/code-data, listing, prefix, xref, intent, call-graph, and decompiler results are reused by the worker pool through a thread-safe memory-bounded LRU. Identity includes the pristine hash, ordered patch history, architecture/effective decoder, analysis schema, guess policy, analyst overrides, and pass inputs; large snapshot hashing and result cloning never run on the render thread.
- **Control-flow graph** (`CFG` + the "Graph (CFG)" mode in Binary View): basic-block partitioning, branch/fallthrough edges, an `ImDrawList` canvas with the live RIP block highlighted.
- **Lightweight decompiler** (`Decompiler` + `DataFlow`, in the Pseudocode view): bounded data-flow reconstruction and CFG structuring recover expressions, `if/else`, and loops, with explicit fallbacks for incomplete or unsupported behavior. Select pseudo-C or Python; both retain clickable source mappings. Scalar shifts preserve logical/arithmetic behavior, widths, and native count masks. Python logical values preserve C's integer 0/1 result and short-circuit evaluation. Function signatures and recovered structure remain heuristic; **Refresh** reruns the analysis.
- **Project persistence** (`Project` + `Json`): version-3 sidecars persist comments, renames, bookmarks, breakpoints (+ validated conditions), ordered byte patches, cursor, notes, listing choices, exact raw mappings, and authoritative function/code/data/type overrides. They are keyed by pristine content hash (`%APPDATA%\DisasmStudio\projects\<hash>.json`), debounced off the render thread, and committed through a flushed temporary file plus atomic replace and `.bak` recovery. Dirty/saving/failure state is visible; close, exit, and target switches synchronously verify the final save. Versions 1–2 migrate on read.
- **Crash-safe preferences and recents** (`Core/AtomicFile` + `Preferences`): project sidecars, the recents index, and `prefs.ini` share flushed sibling-temp/atomic-replace/`.bak` transactions. Reads are capped (64 MiB projects, 4 MiB recents, 64 KiB preferences); a malformed or oversized primary falls back only to a fully validated backup. Symbol-network access defaults off, and a failed preferences commit remains visible rather than silently truncating the last good file.
- **Multi-document analysis workspace** (`Core/DocumentContext`, `Tabs/BinaryViewHostTab`): a top in-window strip supports up to eight static/live-image documents. Each stable document owns its binary, project, decoder, bounded analysis/export workers, caches, metadata, navigation, and retained Binary View state. Opens/switches/closes commit at a frame boundary, dirty documents block on failed saves, and closing joins every borrower before image storage is released. Exact document/image identities retire stale Sig Scanner, Binary Tech, Cortex, transfer, and omnibox results. Debugger, JDWP, Prism, and the epoch-gated live-module analyzer remain global by design.
- **Unified investigation omnibox** (`Ctrl+K`, `Core/InvestigationIndex` + `InvestigationService`): searches commands, exact FILE/LIVE addresses (including VA zero), functions, strings, imports, comments, resources, byte/text hits, xrefs, live modules, typed **Network Trail** findings, and recent queries. Binary View collects immutable snapshots in version-checked render-budgeted slices; one joined worker performs bounded build/ranking with latest-wins coalescing, cancellation, structured failures, and visible dropped/stale counters. Network results can navigate by mapped VA or exact FILE offset, and results never cross a document/debug-session generation.
- **Automatic crackme triage and guided Server Watch** (`Core/CrackmeTriage`, `NetworkApiCatalog`, `NetworkObservation`): load-time analysis scans mapped, file-only, and overlay strings without executing the target, classifies networking imports by exact DLL+API identity, and correlates endpoint, connect, request, reply, and decision evidence through bounded xrefs/call-graph neighborhoods. Its exact return catalog describes each API's success/failure sentinel and output parameters, while bounded function annotation shows whether the return is ignored, checked/branched, stored, propagated, consumed, or returned, with call/use/decision navigation. A checked read status is kept separate from proof that response content was accepted. Binary View's **Triage** lower tab exposes Start Here / Network Trail / Authorization / Strings / Functions / Runtime, Binary Tech hands network findings into it, and Cortex answers both endpoint and return-flow questions. **Open Live Observation** routes to Communications with the originating document/image identity, where an exact matching attachment and an explicit Start Server Watch action are required; it records bounded Winsock, WinHTTP, WinINet, DNS, and URLMon events and separates documented expected returns from validity-bearing observed outcomes/output counts. Static triage never contacts a detected endpoint, and custom TLS or unsupported/dynamic behavior can remain opaque.
- **File/registry authorization triage** (`Core/PersistentStateCatalog`, `AuthorizationAnalysis`, `AuthorizationWatch`): the offline pass also records exact cataloged registry, file, INI, Credential Manager, and DPAPI operations, follows bounded handle/output-buffer provenance, identifies startup reads, and links an allow-path write to the same exact next-launch read and gate. Triage's Authorization view has a filterable, clipper-rendered **Files, Registry & Persistent State** table for every operation, including unlinked evidence; Ctrl+K results focus the exact row. File extensions add search/display hints such as JSON, but never imply a parsed field or accepted value. Relative, computed, source-truncated, unresolved, or incomplete identities cannot form remembered-access links, and static analysis never touches the referenced external resource.
- **Address Inspector** (Binary View lower panel): projects the selected address into file offset, RVA, static VA, and validated runtime module+offset; shows mapping confidence/evidence, FILE/LIVE identity, xrefs, code/data/type classification, analyst overrides, and ordered overlapping-patch coverage. Address validity is explicit, so VA zero remains inspectable.
- **Asynchronous PDB symbols** (`Core/SymbolService`): a sole worker owns DbgHelp resolution for static and live targets, including optional source lines, prototypes/types, and locals. Symbol-server network access is off by default and requires an explicit cache + server opt-in in View -> Symbol Settings; listing lookups stay lightweight while rich inspection is requested only by the PDB / Symbols panel.
- **User comments + symbol renaming**: right-click any instruction → *Set comment…* / *Rename symbol…*. Renames win over export/PDB/heuristic names everywhere they resolve (listing targets, function headers/lists, xrefs, call stack, goto-by-name); comments render inline in the listing. Both persist via the project sidecar.
- **Patch to file**: the Patch popup (asm via Keystone, or raw hex) now *accumulates* patches into the project; **File ▸ Save Binary As…** splices them into a copy of the image on disk via `BinaryFile::vaToOffset`. Patches are listed in the Binary View → *Patches* lower tab (revert/remove) and survive a restart. Live Assembly patches write their runtime address directly; static patches write a debuggee only after exact path/module/bitness matching and checked ASLR translation, otherwise they remain file/project-only.
- **Multi-format + firmware-aware raw loader**: PE32/PE32+, **ELF (32/64, `.dynsym`/`.symtab`, and real `ET_REL` synthetic section layout)**, **Mach-O (thin and universal/fat 32/64, either byte order)**, plus raw shellcode/firmware. Universal images expose bounded slice metadata and deterministically open one supported architecture while preserving VA↔outer-file mapping. `Core/FirmwareSniffer` reports bounded evidence/confidence rather than treating one magic value as proof, suggests mapping/mode/entry, and supplies stable reset/boot/EFI-image landmarks; the raw dialog validates and installs only the analyst-approved backed addresses.
- **Full-program assembly listing** (Binary View → *Assembly*, "Full program" on by default): the worker emits section/PE-header rows, strings, bounded data directives, explicit omitted-tail rows, and fixed 4 KiB executable-page descriptors without decoding instructions. A 64-bit virtual row index and bounded 96-page LRU materialize only visible or explicitly requested pages, with no global instruction cap. A far x86 page uses a <=15-byte/<=120-call estimate, Thumb and compressed RISC-V use aligned <=4-byte candidates, and JVM uses a page-front estimate, all visibly marked provisional. Exact checkpoint work is capped at 64 KiB; a page reconciles when a trusted checkpoint becomes available and otherwise may remain provisional. A `~` row cannot automatically authorize trace or derived analysis, but an explicit Breakpoint/Patch action accepts only that displayed instruction start as analyst authority and marks it `!`; it never promotes the page or seeds trace. Full-program and windowed assembly share this boundary policy. Layout changes carry immutable snapshots/revisions so stale worker results cannot restore an old visibility choice.
- **Source export** (`Core/CodeExport`): **Save ASM…** streams a named/commented assembly listing for any decoded architecture and **Save C…** exports x86/x64 as readable pseudo-C or a self-contained compilable C11 file. C export therefore excludes x86-16; use ASM for real-mode firmware. Both scopes run on the independent cancellable export worker.
- **More architectures**: **x86-16 real mode**, x86/x64, **ARM/A32, Thumb/Thumb-2, ARM64/A64**, MIPS/MIPS64, PowerPC/PowerPC64, and RISC-V 32/64. Zydis uses 16-bit machine/stack widths and Capstone uses `CS_MODE_16`/`CS_MODE_THUMB` for x86-16/Thumb; structured headers otherwise auto-select the arch, while the raw dialog/Engine menu can override. A32/Thumb raw mappings are kept below 4 GiB, and changing the effective ISA invalidates and rebuilds every decode-derived cache. Keystone patch assembly and ISA-correct NOP fill support x86/x64/A32/Thumb/A64.
- **Imports, symbols & loader metadata**: PE IAT and delay-load entries resolve to `DLL.function`; PE base relocations, TLS callbacks, CodeView RSDS GUID/age/PDB paths, security load-config fields, and detailed x64 unwind records are parsed into bounded immutable models. ELF section-table symbols feed the shared Exports / Symbols and Imports models, while class-aware REL/RELA records, mapped relocation targets, PLT/GOT ranges and slots, `DT_NEEDED` dependencies, GNU versions, and init/fini arrays have separate bounded models. Mach-O adds bounded `LC_SYMTAB`, classic dyld bind streams/export tries, function starts, initializer records, and fat-slice metadata. All retain explicit validity/truncation; sectionless ELF `PT_DYNAMIC` and Mach-O chained fixups are not yet implemented.
- **Resource browser** (PE): the resource directory (data directory [2]) is parsed into a bounded Type→Name→Language model (`BinaryFile::resources()`), and a **Resources** lower tab shows the tree with decoded previews — application manifests / HTML as text, `RT_VERSION` version info (file/product version + StringFileInfo pairs), and `RT_STRING` string tables — with a hex fallback for other payloads. Any resource can be saved verbatim, `RT_BITMAP`/`RT_GROUP_ICON` can be exported as standalone `.bmp`/`.ico`, and a resource's bytes are one click from the Hex editor. (Decoders in `Core/ResourceDecode`.)
- **Call graph** (Binary View → *Call Graph*): cached caller/callee edges between discovered functions, navigable around the current function.
- **Switch/jump-table recovery**: right-click an indirect `jmp [reg*n + table]` → *Resolve jump table* reads the table entries (bounded by the section) and lists the case targets.
- **Best-effort type & deobfuscation hints**: the decompiler prepends a heuristic **inferred signature** (arg count from calling-convention register reads, `__int64`/`void` return); timing/privileged/anti-debug instructions (`rdtsc`, `cpuid`, `int 0x2d`, `in`/`out`, …) are flagged inline. Clearly labelled as heuristic.
- **Binary Tech capability scan** (`Core/TechScan`): a real scan over the loaded image — imported-API grouping (anti-debug / network / crypto / injection / dynamic-API / process-spawn), packer/protector section-name signatures (UPX, VMProtect, Themida, ASPack, …), and distinctive byte patterns (direct syscall stub, AES S-box, SHA-256 / MD5 constants). Each hit links to its address with a live disasm/hex preview. (No fabricated results — a clean binary shows few or none.)
- **Signature health**: saved signatures are scored against the loaded binary (none / unique / multiple, with a match count), not hardcoded.
- **Live connections** (Communications): coalesced worker polling for per-process and system-wide IPv4+IPv6 TCP/UDP via the IP Helper API, including scope IDs, TCP state, bounded allocation/ESTATS work, retained history, and surfaced partial-table failures—never a whole-table query on the render thread.

**Still stubbed / out of scope:**
- Connection enumeration covers IPv4 and IPv6 TCP/UDP in both the selected-process pane and the system-wide history monitor, including IPv6 scope IDs. Scripting/plugin automation is intentionally not included.

**Known limitations to be aware of in the debugger:** Step Out single-steps the *current* frame (stepping over calls), so it is bounded by that frame's executed instructions — a pathological in-frame loop that runs past the 500k-instruction safety cap pauses early with a "step out (capped)" status. Hitting a user breakpoint mid-step cancels the in-progress step (you stop on the breakpoint). When you step *over* (or step *out* past) a `call` whose own address holds a software breakpoint, that breakpoint is briefly un-armed while the call runs, so a re-entrant hit *during* the skipped call is not caught. Step Out relies on the executed `ret`/tail-`jmp` actually returning to the call site; a callee that rewrites its own return address (some ROP/obfuscation) won't trip the return breakpoint. Memory scans and pointer searches have explicit byte/work admission bounds and expose partial/cancelled state; scan matches inside the admitted scope are counted exactly and paged. Access to protected targets can still require Administrator, and unavailable cross-bitness module enumeration is surfaced rather than guessed.

## On the performance requirements
The renderer is genuinely GPU-accelerated: it creates a **hardware** D3D11 device (falling back to WARP only if no GPU is available), double-buffered with vsync, and skips rendering when occluded. The Win32 host is per-monitor DPI aware: `WM_DPICHANGED` applies Windows' suggested rectangle and queues a between-frame absolute style/font-atlas/DX11 font-texture rebuild; bursts coalesce to the latest DPI and failed texture creation is retried without rendering an invalid atlas. Stroke widths are rounded to physical pixels. ImGui draws in retained-immediate mode and stays well within frame budget.
