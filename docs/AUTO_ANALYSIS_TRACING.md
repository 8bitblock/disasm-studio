# Automatic analysis and execution tracing — 7 September 2026

## Additions and fixes

- Automatic analysis now considers each service's available workers when choosing global priority. A selected-function request queued behind a busy local worker no longer prevents another document from using a free global slot. Same-document interaction can still interrupt bulk work at cooperative checkpoints; the process-wide 1–8-job limit and borrowed-image lifetime barriers remain unchanged.
- Call-graph and triage caches now include the request's inferred non-returning functions. Decompiler inputs use the same canonical address-set digest. Identifying a callee as non-returning invalidates cached calls and control-flow evidence from its unreachable continuation; duplicate or differently ordered target sets reuse the same cache entry.
- Coalescing an unrelated string/listing request preserves the pending graph's non-returning-function inputs. An explicit newer graph request can replace or clear them.
- Starting, stopping, and restarting coverage now wake the held debug-event owner while paused and are drained before execution commands in the same control epoch. A trace-only queue mutation does not resume the target or change its selected thread or instruction pointer.
- Trace sites require committed executable memory. Guard, no-access, unmapped, data, and natural INT3 sites remain skipped. Failed byte restoration retains physical ownership, exposes its count, and leaves a retryable Stop Trace action available even after a failed restart changed the logical generation.
- One-shot hits rewind the exact thread with checked context readback. The debugger remembers only peer threads already observed at that same trap's post-INT3 instruction pointer, allowing queued duplicate events to execute the restored instruction safely. Per-thread metadata is bounded and retires on an unrelated thread event or module unload. A consumed one-shot needs no new trap-flag step; existing user stepping remains in force.
- Unloading a traced image invalidates address-only historical coverage before another mapping can reuse its base. Restoration failures in other traced modules retain ownership for retry.
- Trace admission enforces a hard maximum of 65,536 unique sites with bounded temporary storage and reports omitted sites. Retained snapshots skip copying/sorting when their generation and revision are unchanged; changed snapshots sort after releasing the recording lock.
- The native planner excludes decoder fallback data rows and retires subsequent boundary authority until another independent loader/analyst/function checkpoint. Inherited listing prefixes and candidate addresses cannot restore that authority. It uses typed call/branch/return semantics, bounds function-root and descriptor traversal per frame, and rejects changed listing topology, decoder configuration, image revision, or module incarnation.
- Listing shading uses bounded contiguous decoded spans. A hit cannot color a folded/data/undecoded gap, a call continuation without its own observation, or bytes beyond the last decoded instruction. FILE evidence retires when its source image/decoder changes. Trace status explains that one-shot entry observations are not loop iteration counts.
- Production-object UI tests accept an explicit object directory, allowing coherent isolated verification when another task or an active application owns the usual Release output.
