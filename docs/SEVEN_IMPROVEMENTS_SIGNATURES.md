# Persistent signature library

- Added a bounded, versioned signature library in `%APPDATA%/DisasmStudio/signatures.json`, with stable 64-bit identities, names, byte patterns and optional architecture/FILE-hash provenance. Starter examples are created only when neither a library nor backup exists; a deliberately empty saved library stays empty.
- Added asynchronous load, save, import and export using one independent I/O job. Save and import publish definitions only after a successful atomic disk write; write failures retain a retryable proposal and remain visible. Startup can recover a valid `.bak` when the primary is corrupt.
- Added native JSON import/export dialogs, selected-signature updates, save-copy and removal. Imports validate the entire file before merging, preserve existing records, skip identical definitions, and allocate new identities for collisions without silently replacing local patterns.
- Kept match health, result counts, target addresses and live-session ownership out of the library. Editing the library retires health, and existing exact-image checks still retire health/results after target changes. Architecture and source hash are descriptive provenance and never authorize a target action.
- Added `signature_library_test` coverage for exact large-ID roundtrips, malformed/oversized JSON, duplicate IDs, invalid patterns, atomic merge rejection, collision remapping, idempotent imports, allocation exhaustion, restart loading, corrupt-primary backup recovery, empty libraries and failed writes.
- Verification: the MSVC C++20 core regression passed with zero failures; the updated `SigScannerTab.cpp` also compiled against the production Win32/ImGui headers. The final Release build, production-object UI regression and startup smoke test passed; see [combined verification](SEVEN_IMPROVEMENTS_IMPLEMENTATION.md).
