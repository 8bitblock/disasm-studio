# Native release UI implementation — 7 September 2026

The approved local design has been integrated into the C++/ImGui application. The design reference is [design-release-v2.html](design-release-v2.html); the architecture work and its remaining scope are recorded separately in [WORKBENCH_PROGRESS.md](WORKBENCH_PROGRESS.md).

## Implemented behavior

- The full nine-feature inventory remains accessible, with active-tab retention and an explicit overflow picker at compact widths. Continue/Pause, Step Into, Step Over, Step Out, Run to cursor and Trace retain labels and checked session/mode enablement.
- Binary View retains all seven representations above a full-height Functions/Strings navigator, central analysis view and lower drawer, and right evidence inspector. Manual optional navigator categories persist through Preferences. Lists retain clipping, bounded caches and existing navigation identities.
- The evidence inspector, lower drawer and Analysis Queue collapse independently. Focus code collapses all three; Registers explicitly reopens the primary register drawer. Existing pane resizing, tools, navigation history and representation pins remain integrated.
- Assembly keeps syntax colors, breakpoint and flow gutters, jump arrows, selection glow, paused RIP and destination highlights. Palette colors remain centralized in Theme; spacing uses native DPI scaling.
- The evidence inspector shows the selected instruction and known destination. A definite conditional-branch outcome requires the actual current paused thread, matching RIP and verified masked instruction bytes. Fresh registers are read after earlier controls or register writes. Running, stale, unsupported and FILE selections do not establish a prediction. FILE activation conclusions use the existing report and are hidden while invalidated analysis refreshes.
- Registers has explicit Edit, Save and Cancel actions, hexadecimal input, clear x64/WOW64 labels, flags and visible error feedback. A draft belongs to one process/session/thread/RIP/bitness; context changes cancel it. Save rechecks the target under the debugger lock. Running values are read-only and the adjacent stack does not read live memory while running.
- Software breakpoint changes wake the paused debugger worker and drain under its held event, before any pending Continue/Step command. Add/remove/condition/every-N requests no longer require resuming the target to become visible. The existing mutex and control-epoch checks also close the queue-to-Running transition race.

It includes `tests/release_workbench_fixture.inc`: real composition at 1920 × 1200 and 1366 × 800, independent pane collapse/reopen, permanent Functions/Strings, manual optional categories and preference restoration, register Edit/Cancel and stale-context retirement. Native GUI verification used the authored `build/ui-register-fixture.exe`. The app loaded the file, showed syntax-colored assembly with jump arrows and selection glow, and launched the fixture paused at entry. A second native session checked the final inspector against real conditional branches. A FILE breakpoint at fixture RVA `0x7309` relocated to the launched module and hit once. Step Over executed the comparison and reached the JNZ at `0x7325`, displaying “Jump will not be taken” with `ZF=1`. The next step fell through to `0x7327`; Step Out returned to the caller at `0x72D4`. The test breakpoint's saved setting was removed and the fixture detached. This check exposed the deferred paused-breakpoint servicing issue addressed above.

The final focused UI suite also passed with zero failures against the current production objects for the layout/inspector changes. It checks both ZF values with an invalid retained LIVE owner, running and non-RIP selections, and suppression of dirty FILE authorization conclusions. The subsequent Core breakpoint fix was verified separately through both full live-debugger fixtures and the native UI check below.

The final rebuilt application was checked again while the authored fixture was paused at entry. Adding a software breakpoint at `0x7FF783A9222A` immediately displayed an armed row. Clicking Remove immediately cleared both the row and gutter marker, without Continue or Step. PID `27576`, TID `23944`, RIP `0x7FF783A92225` and Paused state remained unchanged throughout. The fixture was detached, FILE Strings restored (7,164 entries), and the final application left open with no temporary breakpoint retained.

## Release limits

This is an implemented and tested UI candidate, not a blanket shipping sign-off. Full native accessibility, all-theme contrast, physical multi-monitor DPI transitions, reduced-motion behavior and the entire debugger/analysis regression matrix still require release QA. Immutable image overlays, a complete typed decompiler AST and independent Python emitter, wider type application and remaining debugger subsystem separation are described in WORKBENCH_PROGRESS.md and are not represented as completed by this UI change.
