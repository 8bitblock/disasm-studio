# Debugger startup and memory coverage improvements

- EXE, DLL-host, Authorization Watch, and Adaptive Unpack launches now enqueue owned requests on the existing single-flight debugger lifecycle worker. The UI remains available during startup, timeout, and restoration; the toolbar and Communications expose cancellation.
- Launch completion publishes the exact PID/session only after initial target bitness and main-module metadata are ready. Navigation retains the initiating document/image generation and does not replace a document selected during startup. Starting and Stopping do not grant execution-control authority.
- Queued requests retain their executable path, DLL host plan, containment choice, and Authorization/Server Watch options. Invalid DLL plans are rejected before detaching any existing target. New asynchronous launches require the existing debugger session to be detached first.
- Adaptive Unpack waits for its own launch completion and binds subsequent initialization to the exact target and source document. Closing the workflow cancels pending startup; target/document changes retire observation.
- Debugger memory-region queries now return exact target identity, completeness, the covered prefix, and an error. Unexpected query failures, invalid ranges, region limits, and stale sessions cannot appear as complete memory scope. Legacy vector APIs retain their existing accessible-region filtering.
- Memory Tools displays incomplete-map evidence in its region browser, scan results, and pointer scans. First-scan coverage warnings survive later refinements of the same candidate snapshot. Guard/no-access regions remain unavailable for reads and writes.
- Target-free lifecycle regressions cover both queued launch variants, cancellation/contention, missing executables, invalid DLL plans preserving an existing session, query failures, region caps, normal enumeration end, invalid ranges, and stale target identities.
- Existing x64 and Authorization Watch live fixtures now exercise queued startup, exact completion identity, owned prelaunch evidence, and readable-region coverage.
- Verification on September 7, 2026: `debugger_lifecycle_test`, `x64_debug_test` (live checks required), and `authorization_watch_live_test` passed. The final Release build, production-object UI regression and startup smoke test also passed; see [combined verification](SEVEN_IMPROVEMENTS_IMPLEMENTATION.md).
