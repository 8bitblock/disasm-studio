# Register value origins

- Added “Where did this value come from?” to the FILE Assembly row menu and evidence inspector. Select a general-purpose register to trace its possible sources immediately before the selected x86/x64 instruction. Sources are clickable and highlighted in Assembly; the query stays pinned when following a source.
- Added a bounded backward dependency pass over the current function CFG. Register slices distinguish AL/AH, partial writes, EAX zero extension, copies and extensions, address calculations, and supported scalar transformations. Address zero remains a valid source and navigation destination.
- Kept uncertainty explicit at incoming values, control-flow joins, memory loads, calls, unsupported effects, cycles, incomplete function ownership, and work limits. Results describe static dependencies, not an observed runtime value or a proved path. The first version does not trace memory aliases or enter called functions.
- Routed requests through the existing analysis worker, priority admission and borrowed-image mutation barriers. Requests own their register/function selection and cancellation token; delivery requires the matching request, document image, byte revision, analysis epoch, function generation, and decoder configuration.
- Limited analysis to 4,096 instructions/blocks, 8,192 dependency states, 2,048 sources and 128 displayed boundaries. Sources and boundaries use clipped lists. Cancellation and stale ownership retire highlights and leave an explicit retry path.
- Added core regression coverage for register slices, source address zero, copies, extensions, arithmetic, joins, loops, unknown effects, memory/call boundaries, cancellation and budgets. Analysis-service tests exercise request coalescing, identity, cancellation and worker failures. The production-object UI fixture checks delivery rejection, highlight retirement, source navigation, the inspector/result-drain race and the Assembly menu.
- Verification: `value_origin_test` and `analysis_service_test` passed, and the final Release build and production-object UI regression passed with zero failures. See [combined verification](SEVEN_IMPROVEMENTS_IMPLEMENTATION.md).
