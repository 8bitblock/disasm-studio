🔴 HIGH — fix first
Loaders (untrusted PE/ELF/Mach-O) — one root cause + two reachable OOB reads

BinaryFile.cpp:108 — root cause. rd<T>'s bounds check off + sizeof(T) <= d.size() can wrap when off is near SIZE_MAX, so a wild memcpy passes the guard. Fix: off <= d.size() && sizeof(T) <= d.size() - off. This one fix neutralizes the two below at every call site.
BinaryFile.cpp:402 — ELF e_shoff (64-bit, attacker-controlled) never bounds-checked before indexing the section-name strtab header → OOB read via the wrap above.
BinaryFile.cpp:416 — ELF section-name read from unvalidated strOff + sh_name → OOB read.
Debugger / process control

ProcessManager.cpp:121 — pumpDebugEvent never CloseHandles the handles from CREATE_PROCESS/CREATE_THREAD/LOAD_DLL debug events → a kernel handle leaked per thread-create / DLL-load in the debuggee.
Debugger.cpp:93 — setActiveThread calls GetThreadContext even when the target is running (no state_ == Paused guard, unlike setRegisters) → garbage register values.
Debugger.cpp:552 — when the target byte already reads 0xCC (a second temp bp, or a real int3 in the program), the "original" byte is fabricated as 0x90; on removal it writes a NOP back → silent code corruption.
Detection & scanning

TechScan.cpp:21 — findPattern indexes mask[j] for all j < pat.size() without checking mask.size() >= pat.size() → OOB on vector<bool> (UB) for any mis-sized mask.
SigScannerTab.cpp:86 — live-scan result cap is unenforceable: the inner break only escapes the byte loop, so results_ grows unbounded past 4096 and rescans chunks on a large attached process.
🟡 MEDIUM — correctness / races / leaks
Integer overflow (same class as the HIGHs, lower reachability)

BinaryFile.cpp:263 & :288 — section-containment tests va >= base && va < base + size wrap on 64-bit ELF/Mach-O fields → range confusion; breaks the vaToOffset/offsetToVA inverse. Use no-wrap form va - base < size.
FunctionAnalyzer.cpp:24 — edEnd = edRVA + exportDirSize() wraps in uint32_t → bogus forwarder classification. Compute in 64-bit.
Debugger

Debugger.cpp:170 — pause() TOCTOU: the debug thread can CloseHandle between the atomic load and DebugBreakProcess. Same pattern affects readMemory/writeMemory/regions.
WOW64: the debugger uses the 64-bit CONTEXT/Rip unconditionally — wrong for 32-bit targets (should use Wow64GetThreadContext or reject them).
Debugger.cpp:601 — writeByteRPM/setTempBp ignore the write result → records a breakpoint that was never written (missed stop or stranded 0xCC).
Step-out anchors on "first ret" with no RSP check → stops in the wrong frame for recursive / tail-call code.
Persistence

Project.cpp:135 — duplicate breakpoint addresses break the implicit vector↔bpConditions 1:1 invariant.
